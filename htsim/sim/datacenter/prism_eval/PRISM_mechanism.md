# Prism:基于拥塞分解的喷洒与拥塞控制协同机制

## 概述

在多路径数据中心网络中,发送端同时面对两个相互纠缠的问题:其一,如何在多条并行路径之间分配流量(即喷洒);其二,如何调节发送速率,使网络不致过载(即拥塞控制)。常见做法将二者分别处理,并且往往把"某条路径变慢"笼统地当作拥塞信号——这既可能在本可换路径时盲目降速,也可能在网络确实过载时反应迟缓。

Prism 的基本思想是:把发送端观测到的拥塞信号**分解**成两个含义不同的分量,再用它们分别驱动上述两个决策,从而让喷洒与拥塞控制建立在同一套信号之上、彼此协同。本文描述这一机制的核心:信号如何分解、如何平滑、决策如何做出、以及为什么该机制只需常数级的每流开销。

## 一、拥塞分解与信号平滑

Prism 在一段观测窗口内,持续收集来自不同路径的排队时延。每一个返回的 ACK 都报告了它所经过的那条路径上的排队延迟;由于流量被喷洒到不同路径,相继到达的 ACK 实际上在采样不同的路径。由这一批观测,Prism 在窗口边界提取两个**原始分量**:

- **下界** $C_{cc}$:窗口内排队时延的最小值。它代表"即使最通畅的路径也无法回避的拥塞",衡量网络中确实存在、无处可逃的过载程度。
- **不均衡度** $C_{spray}$:窗口内最大值与最小值之差。它代表"路径之间的不均衡程度",衡量流量在各路径上分布得是否均匀。

两个分量指向不同的成因,也对应不同的对策。下界高,说明问题在于总量过载,应当降低发送速率;不均衡高而下界低,说明仍存在通畅路径、只是流量分布不均,此时降速并无益处,应当交由喷洒把流量重新分散。把这两件事区分开来,是 Prism 与"以单一延迟信号同时调节速率与路径"的方法最根本的不同。

但有一点必须正视:**单个窗口内由少量样本得到的最小值,本身是一个对离群点高度敏感、因而抖动很大的统计量**。若直接用每个窗口的原始 $C_{cc}$、$C_{spray}$ 驱动决策,极易因瞬时采样噪声而在三种状态间频繁跳变,进而引起发送窗口的来回振荡。为此,Prism 不直接使用原始分量,而是对它们沿窗口序列做**指数加权滑动平均(EWMA)**,得到平滑后的下界 $\bar C_{cc}$ 与不均衡度 $\bar C_{spray}$:

$$\bar C_{cc} \leftarrow \beta\, C_{cc} + (1-\beta)\,\bar C_{cc}, \qquad \bar C_{spray} \leftarrow \beta\, C_{spray} + (1-\beta)\,\bar C_{spray}$$

其中 $\beta\in(0,1]$ 是可配置的平滑权重:$\beta$ 越大越贴近当前窗口、反应越快;越小则记忆越长、越平稳($\beta=1$ 退化为直接使用原始值)。**此后所有决策都建立在这一对平滑信号 $\bar C_{cc}$、$\bar C_{spray}$ 之上,而非原始的逐窗口极值。** 平滑以略微的滞后(对突变的反应稍慢、对中等不均衡的利用稍保守)换取了对采样噪声的稳健。

## 二、控制流程

Prism 以"窗口—边界"的节奏运行。一个窗口的长度默认设置为一个 RTT(其具体倍数是一个可配置参数)。窗口进行期间,每收到一个确认,Prism 就更新当前窗口的最小与最大排队时延;当窗口结束时,它先由 min、max 算出原始 $C_{cc}$、$C_{spray}$ 并更新平滑量 $\bar C_{cc}$、$\bar C_{spray}$,再依据**平滑后的**这两个量做出一次判定,在三种状态中选择其一(下面的"高""低"均指相对于可配置阈值 $T_{cc}$、$T_{spray}$):

- $\bar C_{spray} < T_{spray},\ \bar C_{cc} < T_{cc}$:网络通畅且路径均衡,Prism 进入**增窗**状态(Increase),在随后的窗口内逐步提高发送量;
- $\bar C_{spray} \geq T_{spray},\ \bar C_{cc} < T_{cc}$:仍有通畅路径、只是分布不均,Prism **维持**当前发送量不变(Hold),把不均衡交给喷洒去缓解,而不会误将其当作过载来降速;
- $\bar C_{spray} < T_{spray},\ \bar C_{cc} \geq T_{cc}$:判定为真实过载,执行一次**降窗**(Decrease),其降幅随平滑下界超出目标的程度而递增;
- $\bar C_{spray} \geq T_{spray},\ \bar C_{cc} \geq T_{cc}$:下界已超阈、且路径间仍有巨大不均衡,说明负载远高于承受能力,同样**降窗**以尽快回落。

判定所得的状态会一直生效,并逐 ACK 地约束发送量的调整,直到下一个窗口给出新的判定。这种"在窗口内采样、到边界才决策、且决策建立在跨窗口平滑信号之上"的结构,使每一次动作都建立在一段时间的稳健观测之上,而非单个确认或单个窗口的瞬时读数,因而对抖动不敏感。

## 三、每流状态与常数级开销

Prism 为每条流维护的状态,仅是数目固定的若干标量:当前窗口的最小值 $q_{min}$ 与最大值 $q_{max}$、窗口的起始时刻 epoch_start、已采集的有效样本数 samples、当前所处的状态 state,以及平滑后的下界 $\bar C_{cc}$ 与不均衡度 $\bar C_{spray}$。这些量的个数固定不变,不随路径数、并发流数或拥塞窗口大小增长,因此其存储与计算开销都是常数级的。

具体地,这组标量共占 **32 字节**。区分两类量的位宽即可看清:epoch_start 是**绝对时刻**,随仿真增长,需 8 字节;而 $q_{min}$、$q_{max}$、$\bar C_{cc}$、$\bar C_{spray}$ 都是**排队时延**(时长),量级为微秒、远小于 $2^{32}$ 皮秒($\approx 4.29$ ms)的上限,各用 4 字节即可。于是:1 个 8 字节的时刻量(epoch_start)+ 4 个 4 字节的时延量 + 1 个 4 字节的样本计数 samples + 1 个 1 字节的状态 state + 1 个 1 字节的有效标志 genuine_sample = 30 字节,按 8 字节对齐后即 **32 字节**。与原版 Prism 相同——引入平滑没有增加任何字节(见下文其二)。作为对照,需要保留完整样本窗口的中位数类方案,其每流状态随窗口长度线性增长(在同样的每样本位宽下,32/64 长度的中位数窗口分别约 136/264 字节)。

两点使得这一开销在引入平滑后**仍不增加**:

其一,**原始 $C_{cc}$、$C_{spray}$ 无需单独存储**。二者分别就是 $q_{min}$ 与 $q_{max}-q_{min}$,在窗口边界由 min、max 现场算出即可,不占用任何额外的常驻状态。

其二,**平滑也不引入新的状态**。指数加权滑动平均只需保存一个"运行值",而这个运行值恰好就是 Prism 本就需要保留、并在增窗时作为参考的"上一窗口下界/不均衡度估计":平滑量 $\bar C_{cc}$、$\bar C_{spray}$ 与该估计是同一对标量,可以原地更新、复用同一处存储(在每个窗口边界,增窗所参考的下界正是这次更新得到的 $\bar C_{cc}$)。因此"原版 Prism + 平滑"与原版相比,标量的**个数与字节数都不变**,依旧是常数级。

这一常数级性质的更深层根源在于分解所选用的统计量。Prism 所需的是最小值与最大值,而二者都可以**增量维护**:每到达一个确认,只需一次比较即可更新,无需保存任何历史样本。作为对照,若改用诸如中位数这类需要完整样本集合的统计量来刻画路径状况,就必须缓存窗口内的全部观测并加以排序,其状态量随窗口长度增长,计算也更为繁重。Prism 以一对可增量更新的极值(再叠加一层只需运行值的滑动平均),替代了对完整样本窗口的存储——这正是它在获得逐路径感知能力、并对噪声稳健的同时,仍能保持常数级开销的根本原因。

此外,Prism 所用的全部信号都取自发送端已有的确认,既不引入额外的探测报文,也不在数据包中附加任何字段,更不维护任何按路径索引的表项。因此它的开销不仅在量级上是常数级的,在网络传输上也不增加任何额外负担。

## 四、采样的可靠性

三点设计共同保证了分解的可靠性。

其一,只有给出**真实逐路径测量**的 ACK 才被计入最小值与最大值(genuine_sample 为 true)。少数无法提供真实测量、只能退回平滑估计的确认会被排除在统计之外,以免被平滑后的数值污染下界与不均衡度。

其二,一个窗口必须采集到**足够数量**的有效样本(实现中要求不少于三个,epoch_sample ≥ 3)才允许做出判定。最小值、最大值以及二者之差,只有在观测过若干条不同路径之后才具有意义;样本过少时,容易把"只看到一条路径"误判为"路径已经均衡"。若控制窗口的时间已满而样本仍然不足,控制窗口便继续延长,直到样本充足为止。

其三,在增速状态下,Prism 调节每次增幅时所参考的下界,取自上一窗口边界更新得到的**平滑下界 $\bar C_{cc}$**,而非当前窗口尚未收敛的中间值。原因在于,当前窗口的极值要到窗口结束时才最终确定,窗口进行之中只有未定型的中间读数;采用边界处已经定型、且经过跨窗口平滑的 $\bar C_{cc}$,既避免对未定型的中间量过度反应,又抑制了单窗口噪声。平滑下界离目标越近,可用的余量越小,增幅也就越保守。

## 五、发送端算法(伪代码)

Prism 的机制完全位于发送端。下面把前文的机制写成伪代码;所有变量沿用本文**符号表**的记法,而非具体实现的内部命名。模块划分为三块:`sampler`(逐 ACK 采样)、`decompose`(边界处分解 + 平滑)、`controller`(窗口节奏,并在边界处就地判定与执行)。

其中 $\gamma$、$\alpha$ 为降窗 / 增窗的增益,$N_{min}$ 为一个窗口允许判定所需的最少有效样本数(实现中取 3),`cwnd` 为发送窗口;`newly_acked` 为该 ACK 新确认的字节数;`now()` 取当前时刻,`RTT` 取当前往返时延估计。

**一个要点:下面 `controller` 中的增窗式 `cwnd += α·newly_acked·headroom` 与降窗式 `cwnd ×= max(1−γ·…)` 并非 Prism 新设计的控制律,而是底层拥塞控制(本实现中为 NSCC)既有的加性增 / 乘性减,其函数形式与增益 $\alpha$、$\gamma$ 一概沿用、未作改动**(同一套增窗 / 降窗例程也被未分解的 NSCC 直接调用)。Prism 改变的只是这套既有控制律的两件事:其一,**喂给它的信号**——把原本的聚合时延换成分解出的平滑下界 $\bar C_{cc}$,使降窗只对真实过载反应,而非对喷洒造成的不均衡反应;其二,**是否触发**——由四象限的 `state` 充当门控:Hold 状态下增窗与降窗都不执行,把不均衡交给喷洒。换言之,Prism 是叠加在既有 CC 之上的"信号分解 + 决策门控"层,而不是一条新的速率方程;Prism 自身引入的可调量只有平滑权重 $\beta$(默认关闭)。

`state` 在边界之间**持久保存**:它取自上一次边界的判定,被随后窗口内的每个 ACK 读取以决定是否增窗——因此它是每流状态(符号表所列、§三 计入 32B 的 `region`),而非一次性的中间量。

```
# ---- 每流状态与常量 ----
状态(每流):
    q_min, q_max          # 当前窗口排队时延的极值
    C̄_cc, C̄_spray         # 平滑后的下界 / 不均衡度(EWMA 运行值)
    epoch_start           # 当前窗口的起始时刻
    samples               # 当前窗口已采集的有效样本数
    state ∈ {Increase, Hold, Decrease}   # 上一次边界的判定,持久保存
    cwnd                  # 发送窗口
常量:  β∈(0,1]、T_cc、T_spray、κ、N_min=3、γ、α
```

```
# ---- 模块 sampler:逐 ACK 维护极值(只采纳真实逐路径样本)----
function Sample(genuine_sample, q):
    if not genuine_sample:  return     # 非真实逐路径测量 → 不计入极值
    if samples == 0:                   # 本窗口首个有效样本:开窗并记下起始时刻
        epoch_start ← now();  q_min ← q;  q_max ← q
    else:
        q_min ← min(q_min, q);  q_max ← max(q_max, q)
    samples ← samples + 1
```

```
# ---- 模块 decompose:拥塞分解 + EWMA 平滑(窗口边界调用一次)----
function DecomposeAndSmooth():
    C_cc    ← q_min                    # 下界:最通畅路径也无法回避的拥塞
    C_spray ← q_max − q_min            # 不均衡度:路径之间的差异
    if 首个窗口:  C̄_cc ← C_cc;  C̄_spray ← C_spray          # 冷启动种子
    else:        C̄_cc    ← β·C_cc    + (1−β)·C̄_cc          # 原地更新,复用运行值,不新增状态
                 C̄_spray ← β·C_spray + (1−β)·C̄_spray
```

```
# ---- 模块 controller:窗口节奏(每收到一个 ACK 触发)----
function OnAck(genuine_sample, q, newly_acked):
    Sample(genuine_sample, q)                          # 采样

    if state == Increase:                              # 增窗在窗口内逐 ACK 持续生效
        headroom ← T_cc − C̄_cc                         #   参考平滑下界:离目标越近,增幅越保守
        if headroom > 0:  cwnd ← cwnd + α·newly_acked·headroom

    # 边界:时间 ∧ 样本数 双门限 → 分解、平滑,就地判定并执行
    if (now() − epoch_start ≥ κ·RTT) and (samples ≥ N_min):
        DecomposeAndSmooth()
        if   C̄_cc ≥ T_cc:                              # 下界过阈 → 真实过载,降窗
            cwnd ← cwnd × max(1 − γ·(C̄_cc − T_cc)/C̄_cc, 0.5);  state ← Decrease
        elif C̄_spray ≥ T_spray:  state ← Hold          # 仍有通畅路径 → 维持,交给喷洒
        else:                    state ← Increase      # 通畅且均衡 → 增窗
        samples ← 0                                    # 复位;下个有效样本将重新开窗(重置 epoch_start 与极值)
    # 时间已到但样本不足 → 不复位,窗口自动延长,直到样本充足
```

整套流程不引入任何探测报文,也不维护任何按路径索引的表项,每流仅需符号表中那组固定标量(见 §三)。

## 小结

Prism 的机制可以概括为:在约一个往返时延的控制窗口内,用一对可增量维护的极值(最小值、以及最大值与最小值之差)把拥塞信号分解为"真实过载"与"路径不均衡"两个分量;为抑制少量样本带来的抖动,再对二者沿窗口做指数加权滑动平均,并在控制窗口边界依据**平滑后的**下界与不均衡度,分别驱动降速与改路。正因为所需的统计量是极值而非需要完整历史的量、且平滑只需复用一处已有的运行值,Prism 才能在不引入任何额外报文、不维护任何逐路径表项、也不增加每流状态的前提下,以常数级开销获得对多路径拥塞既细粒度又稳健的感知。
